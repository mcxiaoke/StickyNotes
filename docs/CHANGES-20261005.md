- **执行链路**：复用 `SyncHost.SyncNowAsync("manual")` 统一入口（与同步设置窗口的「立即同步」同一条路径），引擎单飞闸继续兜底；下行应用后由既有 `NotesReloadedRequestedMessage` 通道刷新列表，无需额外刷新逻辑。

## 优化同步配置保存与数据流体验（自动同步、状态指标与日志增强）

针对同步设置中修改配置（如启用加密）后的保存与数据流转体验进行了闭环优化：

- **保存自动触发同步**：`SyncHost.ApplySettingsChanged()` 在配置已启用且齐备时自动异步触发一轮同步（`SyncNowAsync("settings_saved")`），使配置修改（如开启远端加密）无需等待 15 分钟轮询即可实时生效并同步。

- **展示上次同步指标**：`SyncState` 增加 `LastUploadedCount`、`LastDownloadedCount` 与 `LastListedCount`；在主设置页“网络同步”分组与同步设置窗口底部状态行统一展示最近同步的时间与上传/下载数（如：`最近同步：2026-10-05 18:30:00（上传 3，下载 0）`），并准确区分“同步未启用”状态。
- **补齐关键步骤日志**：`SyncHost` 记录同步起始原因与配置；`SyncEngine` 补齐口令探针验证通过、远端列表拉取总数、全量对账推导结果统计（待下载/待上传条数）以及上传/下载动作日志。
- **测试覆盖**：全量单元测试 152 项 100% 通过（新增 `SyncStateStore` 指标持久化与反序列化用例）。

## 实现端到端防偷窥加密同步（内置专属密钥与物理双轨隔离）

完成便签网络同步的端到端防偷窥加密功能（方案 1：极简内置口令 + 存储子目录物理隔离）：

- **物理双轨子目录**：明文同步目录为 `stickynotes-data/`，密文保险箱目录为 `stickynotes-vault/`，彻底实现物理分流与隔离。
- **DTO 字段级互斥**：明文模式仅包含 `content` 字段；密文模式仅包含 `iv` 与 `payload` 字段，绝不输出 `content`，杜绝未解密密文入库。
- **魔数守卫与口令探针**：便签正文与口令探针（`.auth_verifier`）均采用 `SN1:` 魔数守卫，彻底杜绝 CBC 伪解密填充误判与损坏数据落盘。
- **专属密钥与轻量混淆**：本地使用 XOR 掩码混淆专属密钥保存在 `VaultSecret.local.cs` 并严格 `.gitignore`；公开仓库保留回落类确保开箱即编译。
- **界面交互**：设置窗口提供「端到端防偷窥加密 (stickynotes-vault)」开关，一键启停，无需记忆与输入密码。
- **全链路测试**：新增 `SyncCryptoTests`（涵盖密钥混淆、加解密、探针、双轨路由与两端加密同步全链路），全量单元测试 151 项 100% 通过（0 失败 0 警告）。

## 新增跨平台防偷窥加密纯函数与 NIST 向量验证套件

在 `scripts/crypto_compat/` 下实现多语言端到端加密/解密纯函数与自动化测试验证套件，覆盖 C# (.NET 8)、Node.js (node:crypto)、Kotlin (Android / javax.crypto)、Python (cryptography)、Dart (Flutter / encrypt+pointycastle) 共 5 种语言。

**核心验证与成果**

- **标准向量通过**：全部语言均 100% 通过 NIST AES-256-CBC Known Answer Test (KAT) 向量（提取自 `temp/KAT_AES/CBCVarTxt256.rsp`、`CBCVarKey256.rsp` 及 NIST SP 800-38A）。
- **应用方案一致**：针对中英文特殊符号、Emoji、多行换行与空白字符混杂内容、空串、整块等边界条件，5 种语言产出的 Base64 密文与明文还原字节级完全一致。
- **环形互通测试**：通过 `scripts/crypto_compat/run_all.ps1` 跑通闭环环形交叉测试（C# 加密 -> Node 解密 -> Kotlin 解密 -> Dart 解密 -> Python 解密 -> C# 解密），100% 精确还原。
- **排雷与修复**：实证发现并修复 Dart `package:encrypt` / PointyCastle 处理空字符串（0 字节）时的 PKCS7 越界异常；全量采用统一的健壮 PKCS7 填充处理。
- **设计方案落盘**：制定并输出完整设计方案文档 [`docs/SYNC-CRYPTO-DESIGN-20261005.md`](file:///c:/Home/Projects/StickyNotesDesktop/docs/SYNC-CRYPTO-DESIGN-20261005.md)，确立“透明字段信封（`ENC:1:` 前缀）+ `SN1:` 魔数守卫 + 探针文件”防偷窥架构，与既有无状态全量对账协议完全正交。

**关于 Wpf.Ui 控件的强调色（已核实，非缺陷）**

- 项目共使用 6 类 Wpf.Ui 控件、120 个实例：`ui:Button` 46、`ui:SymbolIcon` 39、
  `ui:TextBox` 14、`ui:FluentWindow` 10、`ui:ToggleSwitch` 6、`ui:TitleBar` 5；
  手写 `.cs` 中仅 6 处引用（Wpf.Ui 出现的其余位置均为 `obj/` 生成物）。
- 开关呈 `#005CA4`，此为 **Windows 系统个性化强调色**，非 Wpf.Ui 写死色，也非本项目主色。
  源码依据：`UiApplication.ApplySystemAccentColor` 默认为 `true`，启动时自动调用
  `ApplicationAccentColorManager.ApplySystemAccent()`，从 `UIColorType.Accent`
  读取系统强调色注入 `SystemAccentColor` 系列资源。因此该色随系统主题变化。
- 结论：切换主色需先决定产品取向 —— 保持跟随系统强调色（Windows 原生惯例，
  与 FluentWindow / TitleBar 的设计语言一致），或改为固定 `#3B608F` 以严格对齐 M3。
  此前"呈亮蓝色、与主色不协调"的描述不准确，现更正。

**遗留事项**

- 强调色是否固定为 M3 主色，待产品决策（见上节）。
- `CardDefaultBgBrush`（纯白）在无边框场景（如归档窗口空状态）与窗口底色对比仅 1.04，
  边界不可见，后续需补边框或改用 surfaceContainerLow。
- 本轮仅落地浅色。深色模式需先完成 82 处 `StaticResource` → `DynamicResource` 改造，
  否则切换主题不会生效。
